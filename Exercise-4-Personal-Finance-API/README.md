# Personal Finance Tracker API
## Personal Finance Tracker API

A production-shaped Node.js backend for tracking private income and expenses. It includes authentication, ownership-aware CRUD, aggregation reports, role-protected admin analytics, Cloudinary uploads, validation, security middleware, Swagger documentation, seed data, tests, Postman examples, and Render configuration.

## Stack

- Node.js and Express 5
- MongoDB with Mongoose
- JWT authentication and bcrypt password hashing
- Zod request validation
- Helmet, CORS, and rate limiting
- Cloudinary and Multer memory uploads
- Swagger UI at `/docs`

## Run Locally

From the repository root:

```bash
npm install
```

Copy `Exercise-4-Personal-Finance-API/.env.example` to `Exercise-4-Personal-Finance-API/.env` and set:

```env
PORT=5000
MONGO_URI=mongodb://127.0.0.1:27017/personal-finance
JWT_SECRET=use-a-long-random-secret
```

Start the API:

```bash
npm run finance-api
```

The API is available at `http://localhost:5000`. The machine-readable health response is `GET /api`; interactive documentation is `GET /docs`.

## API Routes

| Method | Route | Auth | Purpose |
| --- | --- | --- | --- |
| POST | `/auth/register` | No | Create a user with name, email, and password |
| POST | `/auth/login` | No | Return a JWT |
| GET | `/auth/profile` | JWT | Read the current profile |
| GET | `/transactions` | JWT | List the current user's transactions |
| POST | `/transactions` | JWT | Add income or expense |
| GET | `/transactions/monthly-summary?month=2025-05` | JWT | Aggregate income and expenses by category |
| PUT | `/transactions/:id` | JWT | Edit an owned transaction |
| DELETE | `/transactions/:id` | JWT | Delete an owned transaction |
| GET | `/categories` | JWT | List predefined categories |
| POST | `/upload/profile-picture` | JWT | Upload `profilePicture` to Cloudinary |
| GET | `/admin/overview` | Admin JWT | View users and top spending categories |

Amounts are positive numbers; `type` controls whether the amount is income or expense. Transactions are always filtered by the authenticated user's ID, so one user cannot read or modify another user's records.

```json
  "title": "Monthly rent",
  "amount": 1400,
  "type": "expense",
  "category": "Housing",
  "date": "2025-05-27",
  "notes": "May apartment payment"

```

Object IDs look like `67b2c3d4e5f6789012345678`. More example data is available in the seed script and Postman collection.

## Tests and Tools

```bash
npm test
```

Import `postman/Personal-Finance-Tracker.postman_collection.json` into Postman. It includes register, login, profile, transaction CRUD, monthly summary, categories, and admin requests. Login automatically stores the returned token in the collection.

## Deployment

The root `render.yaml` provisions a Node web service. In Render, provide `MONGO_URI`, `RENDER_URL`, and optional Cloudinary values. `JWT_SECRET` is generated by Render. The deployed Swagger server uses `RENDER_URL`.

For uploads, set `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, and `CLOUDINARY_API_SECRET`. Without those values, the upload route returns `503` rather than silently losing the file.

## Project Layout

```text
Exercise-4-Personal-Finance-API/
  controllers/       Request handlers and aggregation logic
  middlewares/       Validation, uploads, and global errors
  models/            Transaction model and shared User model
  routes/            Auth, transaction, category, upload, admin routes
  postman/           Importable API collection
  tests/             Node built-in smoke tests
  seed.js            Repeatable example data
  swagger.js         OpenAPI definition
  index.js           Express app and MongoDB startup
```

Run from the repository root:

```bash
npm run finance-api
```

Copy `.env.example` to `.env`, set `MONGO_URI` and `JWT_SECRET`, then open `http://localhost:5000/docs`.

## Endpoints

- `POST /auth/register`, `POST /auth/login`, `GET /auth/profile`
- `POST /transactions`, `GET /transactions`, `GET /transactions/monthly-summary`
- `PUT /transactions/:id`, `DELETE /transactions/:id`
- `GET /categories`, `POST /upload/profile-picture`, `GET /admin/overview`

Set `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, and `CLOUDINARY_API_SECRET` to enable profile uploads. The admin overview requires a user whose database `role` is `admin`.
